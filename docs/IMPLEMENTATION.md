# Implementation prompt and acceptance plan
Build the PACKET as a dependency-free Spanish static app called COLECTIVO. Use a forest sidebar, ivory canvas, outlined cards, route map, explicit demo labels and keyboard-accessible controls. Never request real location or personal information.

1. Domain: synthetic nearest-neighbor sensor classifier; generated IDs and timestamps; owner receipt, optional dispatch share, context, first review, independent second review, reopen audit. Reject invalid transitions. Commit domain separately.
2. Interface: Operations, Owner records, Onboarding, Pilot. Coordinate-based interactive map, filterable event queue, event detail and ordered workflow. Fixed-choice forms only. Offline queue survives refresh. Commit functional UI and deploy first.
3. Mechanical: test ownership, state transitions, duplicate delivery, invalid input, thresholds, persistence and browser workflow. Record naturally encountered bugs, fix and add regression. Commit and redeploy.
4. Persona: separate fresh synthetic context using captured screens, dispatcher persona grounded in the brief's limited review time and Spanish/shared-vehicle needs. Log confusion, fix worst issue, retest.
5. Deliver: packet/persona/build-evidence PDFs and 3:30 demo script, README, DECISIONS/session close; publish final commits.

Security: no keys, dependencies, real names or real telemetry; no free text or backend; local storage holds only synthetic data; validate all state/actions and safely render. Role selector is visibly a demo and cannot serve as production auth. Real pilot is blocked until Google Auth/RLS, contributor contracts, support funding, offline hardware drill and retention controls are ready.

Commit plan: packet (done), implementation plan (this), domain, UI/release 1, mechanical fix/release 2, persona fix, final evidence. No fabricated test or release counts.
